# Centralized API Key Management

## The Problem We Solved

Previously, API keys were scattered across multiple locations:
- ❌ `apps/edge/.dev.vars` for backend
- ❌ `apps/mobile/.env` for frontend
- ❌ Manual sync required when updating keys
- ❌ Easy to forget to update both places
- ❌ Different configurations between developers

## The Solution

**Single Source of Truth**: All API keys live in `apps/edge/.dev.vars`

Everything else is automatically derived from this one file.

## How It Works

```
Developer Workflow:
┌─────────────────────────────────────────┐
│ 1. Edit apps/edge/.dev.vars             │
│    OPENAI_API_KEY=sk-proj-...           │
│    ELEVENLABS_API_KEY=your-key          │
└─────────────────────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────┐
│ 2. Run: npm run dev                     │
│    (automatically runs sync-env)        │
└─────────────────────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────┐
│ 3. scripts/sync-env.sh extracts keys    │
│    and generates apps/mobile/.env       │
└─────────────────────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────┐
│ 4. Both backend and frontend have       │
│    correct keys automatically!          │
└─────────────────────────────────────────┘
```

## Quick Start

```bash
# 1. Create .dev.vars from template (one time only)
cd apps/edge
cp .dev.vars.example .dev.vars

# 2. Edit .dev.vars with your actual keys
vim .dev.vars
# Add: OPENAI_API_KEY, ELEVENLABS_API_KEY, etc.

# 3. Sync and start development
cd ../..
npm run dev  # Automatically syncs env vars
```

**That's it!** You never need to manually edit `apps/mobile/.env`.

## What Gets Synced

| Backend (.dev.vars) | Frontend (.env) | Auto-Synced? |
|---------------------|-----------------|--------------|
| `OPENAI_API_KEY` | - | ❌ (backend only) |
| `TAVILY_API_KEY` | - | ❌ (backend only) |
| `ELEVENLABS_API_KEY` | `EXPO_PUBLIC_ELEVENLABS_API_KEY` | ✅ Yes |

The sync script also auto-generates these frontend settings:
- `EXPO_PUBLIC_VOICE_ENABLED` (based on key presence)
- `EXPO_PUBLIC_VOICE_ENGINE=elevenlabs`
- `EXPO_PUBLIC_ELEVENLABS_ENABLED` (based on key presence)
- Voice settings (volume, preset, etc.)

## How to Update Keys

### Local Development

```bash
# Edit the canonical source
vim apps/edge/.dev.vars

# Sync will happen automatically on next `npm run dev`
# Or manually trigger:
npm run sync-env
```

### Production Deployment

#### Cloudflare Workers (Backend)
```bash
cd apps/edge
wrangler secret put ELEVENLABS_API_KEY
# Enter your production key when prompted
```

#### GitHub Pages (Frontend)
```yaml
# .github/workflows/pages.yml
env:
  EXPO_PUBLIC_ELEVENLABS_API_KEY: ${{ secrets.ELEVENLABS_API_KEY }}
```

Add secret in GitHub: **Settings → Secrets → Actions → New repository secret**

## Troubleshooting

### Voice box not showing after adding key?

```bash
# 1. Verify key is in .dev.vars
grep ELEVENLABS apps/edge/.dev.vars

# 2. Re-sync
npm run sync-env

# 3. Check generated .env
cat apps/mobile/.env

# 4. Restart dev server
npm run dev
```

### Sync script says "not found"?

```bash
# Make sure script is executable
chmod +x scripts/sync-env.sh

# Try again
npm run sync-env
```

### Want to sync without starting dev server?

```bash
# Just run sync directly
npm run sync-env
```

### Accidentally edited apps/mobile/.env?

**Don't worry!** Just re-run sync:
```bash
npm run sync-env
```

It will regenerate from `.dev.vars` (the source of truth).
